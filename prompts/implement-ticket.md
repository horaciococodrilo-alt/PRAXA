# Prompt — implementar un ticket

Implementá únicamente el ticket autorizado en `docs/plans/current.md`.

Antes de editar:

1. Confirmá objetivo, scope y no-scope.
2. Indicá secciones de la especificación y ADRs aplicables.
3. Listá archivos, migraciones y dependencias a modificar.
4. Listá pruebas y comandos de aceptación.
5. Señalá cualquier contradicción o decisión humana pendiente.
6. Esperá aprobación si el plan agrega dependencias, cambia arquitectura o amplía alcance.

Durante la implementación:

- Preservá cambios ajenos.
- Hacé el cambio cohesivo más pequeño.
- Agregá pruebas junto con el código.
- No implementes funciones futuras.
- No uses datos reales ni secretos.
- No hagas commit o push salvo instrucción explícita.

Al terminar:

1. Resumí el resultado.
2. Enumerá archivos y migraciones.
3. Informá comandos ejecutados y resultados reales.
4. Mapeá cada criterio de aceptación a evidencia.
5. Declaración de seguridad/tenancy aplicable.
6. Indicá desviaciones, riesgos y deuda.
7. Proponé el siguiente ticket desbloqueado sin implementarlo.
